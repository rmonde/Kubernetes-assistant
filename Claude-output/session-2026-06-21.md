## What Was Built

### `app.py` — Flask HTTP Wrapper

Exposes the RAG pipeline as `POST /ask`. Any HTTP client can now query the assistant.

```python
import importlib
pipeline = importlib.import_module("04_rag_pipeline")
embed = pipeline.embed
search = pipeline.search
build_prompt = pipeline.build_prompt

@app.route('/ask', methods=['POST'])
def user_question():
    data = request.get_json()
    question = data.get('question')

    if not question:
        return jsonify({"success": False, "status_code": 400, "message": "Question is missing"}), 400

    embedding = embed(question)
    results = search(embedding)
    chunk = [result["content"] for result in results]
    answer = build_prompt(question, chunk)
    return jsonify({"answer": answer}), 200
```

```

  -d '{"question": "My pod keeps restarting and the status shows OOMKilled"}'
→ {"answer": "Your pod keeps restarting because the container exceeded its memory limit..."}  ✅
```

## Bugs Fixed This Session

| Bug | Root Cause | Fix |
|---|---|---|
| `from 04_rag_pipeline import ...` | Python module names can't start with a digit — SyntaxError at startup | Use `importlib.import_module("04_rag_pipeline")` |
| `print(answer)` with no return | Answer sent to terminal, not to HTTP client — silent wrong behaviour | `return jsonify({"answer": answer}), 200` |

**Key lesson — silent vs loud bugs:**
- `SyntaxError` on import = immediately obvious, app won't start
- Missing `return` in a route = silent, app starts fine, client gets `None` — harder to catch
